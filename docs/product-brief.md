# CarbonCap — Product Brief

วันที่: 3 พฤศจิกายน 2026

สถานะ: สร้างต้นแบบ HTML ไฟล์เดียวผ่าน DeepSeek/TokenMe ครบแล้ว ฝังภาพ Google Earth Engine จริง 6 ภาพ และตรวจ UX/UI ผ่านเบราว์เซอร์บน desktop กับมือถือแล้ว

## 1. แนวคิดและเป้าหมาย — ยืนยันแล้ว

CarbonCap เป็นแนวคิดบริการที่ใช้ AI และข้อมูลดาวเทียมช่วยประเมินการกักเก็บคาร์บอนในพื้นที่เกษตร แล้วสื่อสารโอกาสสร้างมูลค่าผ่านคาร์บอนเครดิต

ต้นแบบนี้ทำให้ผู้ใช้ทดลองเส้นทางตั้งแต่สำรวจโครงการ ดูผลวิเคราะห์และหลักฐานตัวอย่าง ประเมินมูลค่า ทดลองซื้อเครดิต จนเห็นรายการในพอร์ต โดยผลวิเคราะห์คาร์บอน ราคา และธุรกรรมเป็นการจำลอง ส่วนภาพดาวเทียมและชั้นข้อมูลนำมาจากผลส่งออกของ Google Earth Engine

## 2. ผู้ใช้หลัก — ยืนยันแล้ว

- นักลงทุนที่ต้องการประเมินศักยภาพของแนวคิดและโครงการ
- ผู้ซื้อคาร์บอนเครดิตที่ต้องการสำรวจโครงการ เข้าใจข้อมูลประกอบ และทดลองขั้นตอนซื้อ

ประสบการณ์หลักมุ่งไปที่การสำรวจและทดลองซื้อเครดิตของผู้ซื้อ มากกว่าขั้นตอนลงทะเบียนแปลงของเกษตรกร

## 3. ขอบเขตและข้อกำหนด — ยืนยันแล้ว

- ผลงานหลักเป็น HTML ไฟล์เดียวที่กดใช้งานได้ครบ flow
- ฝัง CSS, JavaScript และภาพที่ส่งออกจาก Google Earth Engine ไว้ในไฟล์ เปิดออฟไลน์ได้ทั้งหมด โดยไม่เรียกบริการภายนอกขณะใช้งาน
- ภาษาไทยเป็นหลัก ชื่อแบรนด์ CarbonCap
- เลือก Google Earth Engine เป็นแหล่งข้อมูลและการประมวลผลภาพดาวเทียม
- ใช้ข้อมูลจำลองสำหรับผล AI ด้านคาร์บอน ปริมาณคาร์บอน ราคา และธุรกรรม โดยแยกจากแหล่งที่มาของภาพดาวเทียม

### การใช้ Google Earth Engine — ยืนยันวิธีแล้ว

- ส่งออกภาพดาวเทียมและชั้นข้อมูลจาก Earth Engine แล้วฝังใน HTML เพื่อให้เปิดออฟไลน์ได้
- แสดงแหล่งข้อมูล ช่วงวันที่ และระบุว่าเป็นภาพที่บันทึกไว้
- ใช้ Earth Engine ในขั้นเตรียมข้อมูล โดยไม่เรียก Earth Engine API ขณะเปิดต้นแบบ
- ไม่แสดงภาพจำลองเป็นภาพที่ได้จาก Earth Engine จริง
- ใช้ Sentinel-2 สำหรับภาพสีจริงและชั้นพืชพรรณ NDVI
- ผู้ใช้มอบหมายให้ Codex เลือกพื้นที่เกษตรตัวอย่างในไทย 3 แห่งและช่วงภาพที่เหมาะสม โดยบันทึกแหล่งที่มาและช่วงวันที่จริง
- ผลคาร์บอนและการซื้อยังเป็นข้อมูลจำลอง แยกจากภาพดาวเทียมจริง
- ส่งออกภาพ RGB และ NDVI สำเร็จแล้วสำหรับแม่ริม เชียงใหม่; ท่าใหม่ จันทบุรี; และปากช่อง นครราชสีมา
- ใช้ภาพในช่วงมกราคม–มีนาคม 2026 รายละเอียดวันที่จริง จำนวนภาพ และ checksum อยู่ใน docs/gee-manifest.json

## 4. เส้นทางหลัก — ยืนยันแล้ว

เลือกโครงการเกษตร → ดูหลักฐานและผล AI จำลอง → คำนวณมูลค่า → ทดลองซื้อเครดิต → ดูพอร์ต

## 5. หน้าจอและ interaction — ยืนยันแล้ว

### หน้าสำรวจโครงการ

- แสดงภาพดาวเทียมหรือชั้นข้อมูลที่ส่งออกจาก Google Earth Engine เป็นองค์ประกอบหลัก ร่วมกับโครงการตัวอย่าง 3 โครงการ
- กดเลือกโครงการจากแผนที่หรือรายการ แล้วแสดงข้อมูลของโครงการที่เลือกให้สอดคล้องกัน
- กรองโครงการและสลับชั้นข้อมูลคาร์บอน/พืชพรรณได้
- แยกป้ายแหล่งภาพดาวเทียมออกจากป้ายโครงการตัวอย่างและผลคาร์บอนจำลอง

### รายละเอียดโครงการและผล AI

- ดูข้อมูลโครงการ หลักฐานตัวอย่าง ผลวิเคราะห์ AI จำลอง และสถานะเครดิต
- กดทดลองวิเคราะห์ แล้วเห็นสถานะกำลังวิเคราะห์ก่อนแสดงผลจำลอง
- แสดงช่วงคาร์บอนประมาณการ พร้อมคำอธิบายว่าค่าประมาณยังไม่ใช่เครดิตที่พร้อมซื้อ
- แยกปริมาณคาร์บอนประมาณการออกจากจำนวนเครดิตพร้อมซื้อ
- โครงการที่ยังอยู่ระหว่างประเมินใช้การติดตามโครงการ ส่วนโครงการที่มีเครดิตพร้อมซื้อในสถานการณ์จำลองจึงเข้าสู่ขั้นตอนทดลองซื้อได้

### คำนวณมูลค่าและทดลองซื้อ

- ผู้ใช้ระบุจำนวนเครดิตที่ต้องการทดลองซื้อ
- แสดงราคาต่อเครดิตและมูลค่ารวมจำลองตามจำนวนที่เลือก
- ตรวจทานรายละเอียดก่อนยืนยันซื้อจำลอง
- หลังยืนยัน แสดงผลสำเร็จว่าเพิ่มรายการในพอร์ตจำลองแล้ว

### พอร์ตจำลอง

- เริ่มต้นด้วยสถานะยังไม่มีรายการ และมีทางกลับไปสำรวจโครงการ
- เพิ่มรายการหลังผู้ใช้ยืนยันซื้อจำลอง
- บันทึกข้อมูลในเบราว์เซอร์เพื่อให้กลับมาเปิดดูต่อได้
- มีปุ่มล้างข้อมูลเพื่อเริ่มทดลองใหม่

## 6. ทิศทาง UX/UI

ยืนยันแล้ว:

- แดชบอร์ดลงทุนโทนสว่าง เขียวเข้ม เรียบหรู
- แผนที่เป็นจุดเด่นของประสบการณ์
- ภาษาไทยเป็นหลัก

รายละเอียดที่ยืนยันแล้ว:

- จัดลำดับให้เห็นโครงการที่เลือก ข้อมูลประกอบ และการกระทำถัดไปได้ชัดเจน
- ตัวเลขและหน่วยอ่านง่าย แยกค่าประมาณ ราคา และจำนวนเครดิตออกจากกัน
- แสดงสถานะการเลือก การวิเคราะห์ และการซื้อให้ผู้ใช้รับรู้
- รองรับการใช้งานทั้งคอมพิวเตอร์และมือถือ
- แสดงข้อความสั้นอย่างต่อเนื่องว่าข้อมูลโครงการ ผลคาร์บอน และธุรกรรมเป็นการจำลอง พร้อมระบุแหล่งภาพดาวเทียมตามจริง

## 7. การสื่อสารเรื่องคาร์บอน — ยืนยันแล้ว

- ใช้คำว่า “คาร์บอนประมาณการ” สำหรับผลประเมิน และ “เครดิตพร้อมซื้อ (จำลอง)” สำหรับเครดิตที่ซื้อได้ในสถานการณ์ตัวอย่าง
- การประเมินด้วย AI/ดาวเทียมไม่ทำให้เกิดเครดิตพร้อมซื้อโดยอัตโนมัติ
- ไม่แสดงราคาหรือมูลค่าจำลองเป็นรายได้หรือผลตอบแทนที่รับประกัน
- หลังซื้อใช้ข้อความ “เพิ่มในพอร์ตจำลองแล้ว” โดยไม่สื่อว่ามีการชำระเงินจริงหรือใช้เครดิตชดเชยการปล่อยแล้ว
- ไม่ใช้ข้อมูลจำลองอ้างว่าเป็นผลวัดจริงหรือการรับรองจริง

ข้อมูลประกอบการออกแบบ:

- [TGO — ขั้นตอนการออกคาร์บอนเครดิต](https://tver.tgo.or.th/en/premium-tver/project-development/procedure-for-carbon-credits-issuance): การออกเครดิตมีขั้นตอนติดตาม คำนวณ ทวนสอบ และรับรอง ก่อนออกเข้าบัญชีทะเบียน
- [Verra — VT0014](https://verra.org/methodologies/vt0014-estimating-organic-carbon-stocks-using-digital-soil-mapping-v1-0/): การประเมินคาร์บอนอินทรีย์ในดินด้วยแบบจำลองและข้อมูลภูมิสารสนเทศมีการปรับเทียบ ตรวจสอบ และประเมินความไม่แน่นอน
- [Verra — FAQ](https://verra.org/faq/): การซื้อหรือถือครองเครดิตแยกจากการนำเครดิตออกจากการหมุนเวียนเพื่อใช้ชดเชย
- [Google Earth Engine — Client-side web apps](https://developers.google.com/earth-engine/custom-apps/client-js): แนวทางแสดงผลประมวลผล Earth Engine ในเว็บและการยืนยันตัวตน
- [Google Earth Engine — Image visualization](https://developers.google.com/earth-engine/guides/image_visualization): การสร้างภาพสำหรับแสดงผลและส่งออกภาพตัวอย่าง
- [Earth Engine Data Catalog — Sentinel-2 SR Harmonized](https://developers.google.com/earth-engine/datasets/catalog/COPERNICUS_S2_SR_HARMONIZED): ชุดภาพ Sentinel-2 ที่เลือกใช้สำหรับเตรียมข้อมูล

- บันทึกคำศัพท์ใน GLOSSARY.md และสร้าง ADR เฉพาะเมื่อมีการตัดสินใจที่เข้าหลักเกณฑ์
- เมื่อสร้างและตรวจงานเสร็จ ให้สร้าง GitHub repository ชื่อ CarbonCap แบบ Private ในบัญชีของผู้ใช้

## 9. เกณฑ์ตรวจรับ — ยืนยันแล้ว

- เปิด HTML โดยไม่เชื่อมอินเทอร์เน็ตแล้วแสดงผลและกดใช้งานได้ รวมถึงภาพดาวเทียมและชั้นข้อมูลที่ฝังไว้
- ภาพที่ระบุว่ามาจาก Earth Engine ต้องมีแหล่งที่มาตรงกับข้อมูลจริง ส่วนผลคาร์บอนจำลองต้องระบุแยกกัน
- ทดลอง flow หลักได้ตั้งแต่เลือกโครงการจนเห็นรายการซื้อในพอร์ต
- การเลือกโครงการและการสลับชั้นข้อมูลเปลี่ยนสิ่งที่แสดงจริง
- การระบุจำนวนเครดิตเปลี่ยนมูลค่ารวมได้ถูกต้อง
- โครงการที่ยังประเมินอยู่ไม่เข้าสู่การซื้อเครดิตพร้อมซื้อ
- บันทึกพอร์ตและล้างข้อมูลเริ่มใหม่ได้
- ใช้งานได้ทั้งบนคอมพิวเตอร์และมือถือ โดยข้อความและปุ่มหลักไม่ถูกตัด
- ป้ายข้อมูลจำลองและความแตกต่างระหว่างค่าประมาณกับเครดิตพร้อมซื้อชัดเจน

## 10. ผลงานและการตรวจรับ

- ผลงานหลัก: index.html ขนาดประมาณ 9 MB ฝัง CSS, JavaScript และภาพ RGB/NDVI ทั้ง 6 ภาพ ไม่มีทรัพยากรภายนอกที่ต้องโหลด
- DeepSeek เป็นผู้เขียนและแก้โค้ดผ่าน TokenMe โดยแบ่งงานเป็นส่วนย่อย Codex เตรียมข้อมูล กำหนดงาน และตรวจรับ
- เอกสารประกอบ: README.md, GLOSSARY.md, ADR, docs/gee-manifest.json และ docs/imagery-provenance.md
- Repository แบบ Private: [MatchaGtea/CarbonCap](https://github.com/MatchaGtea/CarbonCap)

ตรวจผ่าน:

- แสดงภาพจริง เลือกพื้นที่ สลับชั้น RGB/NDVI/คาร์บอนจำลอง ค้นหา กรอง และล้างตัวกรอง
- วิเคราะห์จำลองพร้อมสถานะโหลด ผลลัพธ์ และการสลับโครงการระหว่างวิเคราะห์ โดยงานเก่าไม่รบกวนงานใหม่
- ปฏิเสธจำนวนว่าง ศูนย์ ติดลบ เศษ และเกินยอด; คำนวณยอดถูกต้อง; ตรวจทาน ยกเลิก และยืนยันซื้อได้
- พอร์ตและประวัติธุรกรรมคงอยู่หลังรีเฟรช; ติดตามโครงการรอประเมินได้; ซื้อโครงการรอประเมินไม่ได้
- ซื้อจนหมดสต็อกแล้วหยุดการซื้อเพิ่มได้; รีเซ็ตคืนยอดเครดิตและล้างรายการกับข้อความสำเร็จ
- หน้าจอ desktop 1440px และมือถือ 390px ไม่ล้นแนวนอน ปุ่มหลักบนมือถือมีความสูงอย่างน้อย 44px
- ไม่พบ console error; JavaScript ผ่านการตรวจไวยากรณ์; ภาพที่ฝังทั้ง 6 ภาพมี SHA-256 ตรงกับผลส่งออกจริง

ข้อจำกัดการตรวจ: เบราว์เซอร์ QA บล็อกการเปิด file:// จึงทดสอบ UI ผ่าน localhost และตรวจว่าไม่มีทรัพยากรภายนอกที่ต้องโหลด ยังไม่ได้ทดสอบเปิด file:// โดยตรง พฤติกรรม localStorage สำหรับไฟล์ในเครื่องอาจแตกต่างตามเบราว์เซอร์ โดยแอปมีทางทำงานในหน่วยความจำเมื่อบันทึกไม่ได้
